The Nenya REST API gives you full access to tasks, notes, and categories over HTTP. Use it to build integrations, automations, or custom clients.

## Base URL

```
https://api.nenyahq.com/functions/v1/api
```

All endpoints are prefixed with `/v1/`.

## Authentication

Every request must include an `Authorization` header with a Bearer token. Nenya supports two token types:

<Tabs>
  <Tab title="API Key">
    Generate an API key from the [Nenya app](https://app.nenyahq.com) under **Settings > API Keys**.

    ```bash
    curl https://api.nenyahq.com/functions/v1/api/v1/tasks \
      -H "Authorization: Bearer nenya_sk_your_key_here"
    ```
  </Tab>
  <Tab title="JWT Token">
    Use a Supabase Auth JWT token for client applications.

    ```bash
    curl https://api.nenyahq.com/functions/v1/api/v1/tasks \
      -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."
    ```
  </Tab>
</Tabs>

## Response format

All responses return JSON with a consistent structure:

**Success:**
```json
{
  "data": { ... },
  "count": 10
}
```

**Error:**
```json
{
  "error": "Description of what went wrong"
}
```

## HTTP status codes

| Code | Description |
| ---- | ----------- |
| `200` | Success |
| `201` | Created |
| `400` | Bad request (invalid parameters) |
| `401` | Unauthorized (missing or invalid token) |
| `404` | Resource not found |
| `500` | Internal server error |

## Endpoints

### Tasks

| Method | Endpoint | Description |
| ------ | -------- | ----------- |
| `GET` | [`/v1/tasks`](/api-reference/tasks/list) | List tasks with filters |
| `GET` | [`/v1/tasks/:id`](/api-reference/tasks/get) | Get a single task |
| `POST` | [`/v1/tasks`](/api-reference/tasks/create) | Create a task |
| `PATCH` | [`/v1/tasks/:id`](/api-reference/tasks/update) | Update a task |
| `DELETE` | [`/v1/tasks/:id`](/api-reference/tasks/delete) | Delete a task |
| `POST` | [`/v1/tasks/:id/complete`](/api-reference/tasks/complete) | Toggle task completion |
| `POST` | [`/v1/tasks/reorder`](/api-reference/tasks/reorder) | Reorder tasks |
